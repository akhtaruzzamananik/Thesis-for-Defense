## Verified citation

Dehghani, M., & Zoroofi, R. A. (2025). AI-Driven Dental Disease Detection: A Web-Based Application Utilizing an AI Engine for Panoramic Image Analysis. In *2025 11th International Conference on Web Research (ICWR)* (pp. 61–65). IEEE. https://doi.org/10.1109/icwr65219.2025.11006210 (PDF p. 1).

## question/task/modality

- **Modality:** 2D panoramic dental X-ray images (`PNG` format in `DENTEX`; web application ingests `DICOM` and converts to `PNG`, pp. 1–3).
- **Task:** (1) **4-class pathology bounding-box detection** (`Caries`, `Deep Caries`, `Impacted`, `Periapical Lesion`) on the public **`DENTEX`** dataset comparing customized **`YOLOv11`** and **`YOLOv8`** models against literature baselines (`DINO`, `YOLOv8`, `DINO + YOLOv8` `[8]`, and `YOLOrtho` `[20]`), and (2) **Web-based clinical reporting application** built with an HTML/CSS frontend, **Flask** backend, PyTorch AI engine, and **PostgreSQL** database (`patients`, `images`, `reports` tables) with radiologist report-editing tools and patient report links (`pp. 1–4, Figs. 1–2`).

## data/counts

- **Dataset (`p. 3, Table I`):** Public **`DENTEX` (`Hamamci et al., 2023`, `arXiv:2305.19112`, Ref `[10]`)** dataset comprising `705` training PNGs and `50` validation PNGs. The authors used the **`705` training folder images** with **`3,529` annotated pathology instances** across `4` classes (`Table I`, p. 3):
  - `Caries`: **`799`** instances
  - `Deep Caries`: **`942`** instances
  - `Impacted`: **`823`** instances
  - `Periapical Lesion`: **`965`** instances.

## annotation

- **Provenance (`p. 3`):** Public `DENTEX` hierarchical bounding-box annotations. Authors explicitly note on `p. 3` that *"the specific labeling methodology and the qualifications of the labelers are not disclosed"* in the dataset (`kappa` `not reported`).

## split

- **Validation scheme (`p. 3`):** **5-fold cross-validation** across the `705` `DENTEX` training images (`Tables II–III` report averages across the 5 folds; `Fig. 3` plots the normalized confusion matrix for the final fold). Patient-level grouping is `not reported` (`DENTEX` images are anonymized).

## model

- **Architectures (`p. 2`):**
  - `Customized YOLOv11`: Adds an extra Spatial Pyramid Pooling Fast (`SPPF`) layer after the convolution and `C3k2` stage prior to final processing; **`459` layers, `90,471,292` parameters (`~90.47M`)**.
  - `Customized YOLOv8`: Adds an extra convolutional layer at the end; **`407` layers, `75,457,900` parameters (`~75.46M`)**.
- **Web Application Stack (`p. 2, Fig. 1`):** HTML/CSS frontend + Python **Flask** backend + PyTorch AI engine + **PostgreSQL** (`patients`, `images`, `reports` relational tables; `DICOM -> PNG` conversion).

## preprocessing

- **Operations (`pp. 2–3`):** Resized to `640 × 640` pixels; authors explicitly state: *"Notably, no preprocessing techniques were applied to either the training or validation datasets"* (no `CLAHE` or filtering).

## training

- **Hyperparameters (`p. 2`):** `100` epochs, batch size `16`, input resolution `640 × 640`. Optimizer, learning rate, and augmentation settings: `not reported`.

## metrics/IoU

- **Reported metrics (`p. 3, Tables II–III`):** Average Recall (`AR` / Recall, Eq. 2), Average Precision (`AP` / Precision, Eq. 1), `AP50` (`mAP@0.50`), and `AP50-95` (`mAP@0.50:0.95`).

## timing/hardware

- **Hardware (`p. 3`):** Workstation with `128 GB` system RAM and **dual NVIDIA RTX 3090 GPUs** (text on p. 3 states *"each with 48GB of dedicated memory"*, which is a hardware spec confusion since an RTX 3090 has `24 GB` VRAM each, or `48 GB` combined across two cards).
- **Inference speed (`FPS` / ms per image) and web app response latency:** **`not reported`**.

## results with locators

- **Overall 5-Fold Cross-Validation Summary (`Table II`, p. 3 — `AR / AP / AP50 / AP50-95`):**
  - `DINO [8]`: `0.544 / 0.343 / 0.508 / NR`
  - `YOLOv8 [8]`: `0.530 / 0.352 / 0.539 / NR`
  - `DINO + YOLOv8 [8]`: `0.592 / 0.371 / 0.543 / NR`
  - `Customized YOLOv8`: `0.537 / 0.512 / 0.507 / 0.329`
  - **`Customized YOLOv11`:** **`0.621 / 0.583 / 0.590 / 0.391`**.
- **Class-wise 5-Fold Cross-Validation Performance (`Table III`, p. 3 — `AR / AP / AP50 / AP50-95`):**
  - *`Customized YOLOv8`:*
    - `Caries`: `0.454 / 0.382 / 0.381 / 0.269`
    - `Deep Caries`: `0.419 / 0.579 / 0.486 / 0.289`
    - `Impacted`: `0.866 / 0.808 / 0.840 / 0.532`
    - `Periapical Lesion`: `0.310 / 0.379 / 0.321 / 0.226`
  - *`Customized YOLOv11`:*
    - `Caries`: `0.446 / 0.405 / 0.403 / 0.283`
    - `Deep Caries`: `0.543 / 0.426 / 0.421 / 0.254`
    - **`Impacted`:** **`0.908 / 0.796 / 0.871 / 0.552`**
    - `Periapical Lesion`: `0.345 / 0.328 / 0.322 / 0.214`.

## limitations

- **Author-stated (`pp. 3–5`):** (1) Weak detection performance on `Periapical Lesion` (`AP50 = 0.322`, `AP50-95 = 0.214`) despite it having the largest instance count (`965`); (2) standard geometric augmentations (rotation, resizing) and class weighting did not resolve performance gaps on interconnected panoramic dental structures; (3) outputs require specialist review before finalizing reports.

## critique

- **Three major methodological and mathematical audit findings (`OS §3.2`):**
  1. **Internal contradiction between `Table II` and `Table III` (`p. 3`):** In `Table III`, the 4-class arithmetic average for `Customized YOLOv8` is `AR = 0.5123, AP = 0.5370, AP50 = 0.5070, AP50-95 = 0.3290` (matching `Table II` except `AR` and `AP` are swapped!). However, for `Customized YOLOv11`, the 4-class arithmetic average of `Table III` is **`AR = 0.5605, AP = 0.4888, AP50 = 0.5043, AP50-95 = 0.3258`** — which is slightly **lower** on `AP50` (`0.5043` vs `0.5070`) and `AP50-95` (`0.3258` vs `0.3290`) than `Customized YOLOv8` (`Deep Caries AP50` dropped from `0.486` to `0.421` and `Periapical AP50-95` dropped from `0.226` to `0.214`), contradicting the `0.621 / 0.583 / 0.590 / 0.391` summary row in `Table II`!
  2. **Metric definition conflation (`Precision` vs `COCO mAP@[0.5:0.95]`):** Equations 1–2 (`p. 3`) define `AP` as box `Precision = TP/(TP+FP)` and `AR` as `Recall = TP/(TP+FN)`, yet `Table II` compares their `AP` (`0.583`) against `He et al. [8]` (`0.371`) and `YOLOrtho [20]` (`0.357`), where `0.371` and `0.357` were actually **`COCO mAP@0.5:0.95`** (`AP` in COCO notation), leading to the inflated claim of a `>21%` precision improvement!
  3. **No latency or deployment validation (`G6`):** Presents a Flask + PostgreSQL web UI (`Fig. 2`) but reports zero inference latency (`ms`/`FPS`) or user testing.

## reuse

- **Primary citation for:**
  - **`S16` (`STEP-036` Web-Based Diagnostic Demo):** Alongside `P0001` (`Panognostics-Plus`), provides a direct architectural reference (`Flask + HTML/CSS + PyTorch + DICOM/PNG`) that our `S16` web app improves upon by reporting real-time latency, calibrated confidence filtering, and reproducible local execution.
  - **`STEP-010` Public Benchmark (`DENTEX`):** Documents the 4-class `DENTEX` pathology counts (`705` OPGs: `799 Caries`, `942 Deep Caries`, `823 Impacted`, `965 Periapical Lesion`) and confirms that on `DENTEX`, `Impacted` is easiest (`AP50 = 0.840–0.871`) while `Periapical Lesion` (`0.321–0.322`) and `Caries` (`0.381–0.403`) are much harder.
  - **`G4` / `G5` (Metric conflation & table audit):** Textbook example of confusing `Precision = TP/(TP+FP)` with `COCO AP (mAP@0.5:0.95)` when comparing against prior literature.

## conflicts
